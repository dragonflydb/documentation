# ACL Categories

Every Dragonfly command belongs to one or more ACL categories.
A rule `+@<category>` lets a user run every command in the category, and `-@<category>` takes them away again.
Rules apply in order, as described in [Access Control Lists](./acl.md#acl-groups).

```shell
dragonfly> ACL SETUSER reporter ON >secret ~* -@all +@read
OK
```

## Category Names

The names are the ones `ACL CAT` returns, and a few differ from Redis and Valkey:

- HyperLogLog commands are in `@hyperlog`. Dragonfly rejects `+@hyperloglog` with `ERR Unrecognized parameter`.
- Dragonfly adds `@bloom`, `@cms`, `@cuckoo_filter`, `@ft_search`, `@json`, `@throttle` and `@topk` for its Redis Stack compatible commands.
  `+@search` is accepted as an alias of `+@ft_search`.

## Subcommands

A subcommand listed below as `CMD|SUB` has its own ACL entry and its own categories.
`+client|kill` grants only `CLIENT KILL`, and `+@all -client|kill` denies only `CLIENT KILL`.
For `CLIENT` and `MEMORY`, a rule for the container also covers these subcommands:
`+client` grants `CLIENT KILL`, and `-memory` denies `MEMORY ARENA`.

`ACL` is different: each `ACL` subcommand is a command of its own.
`+acl` and `-acl` change only the bare `ACL` command, so `+@all -acl` still allows `ACL SETUSER`.
Use `-acl|setuser` and the other `-acl|<subcommand>` rules, or `-@admin`, to take them away.

Every other subcommand runs under the categories of its container.
For example, `CLIENT GETNAME` has the categories of `CLIENT`, and a rule `+client|getname` is rejected with `ERR Unrecognized parameter`.

`XGROUP HELP` is served by the hidden command `_XGROUP_HELP`, so `+xgroup` does not grant it, while `+_xgroup_help` or one of its categories does.
`DFLY` and `DFLYMIGRATE` are internal replication and slot-migration commands, and `GAT` serves the Memcached protocol.
